# ADR 0001 支持可选模型网关

状态：已采用

## 背景

独立 GUI Runtime 和实机评测需要能通过模型网关访问多个供应商。任务恢复和产物验收依赖既有 checkpoint 和接口。模型路由可能增加一次转发，并改变模型别名所指向的部署。

## 备选与决定

| 备选 | 取舍 |
| --- | --- |
| 只开放通用 `--endpoint` | 接口最少，使用者需手动拼完整路径和管理 Key。 |
| 将 LiteLLM SDK 引入核心 Runtime | 可直接调用 SDK 路由功能，增加运行依赖并扩大核心层职责。 |
| **通过现有 Chat Completions 客户端提供 LiteLLM Proxy 选项** | 保持执行端的模型协议，网关部署和路由配置在 Runtime 外。 |

采用第三项。`--litellm-base-url` 使用单独的网关 Key。外部接入配置放在命令入口与模型客户端侧。核心继续通过已有 planner 和 backend 接口执行。

## 后果与验证

Runtime 仍要求模型输出 JSON 决策。依赖截图的任务需要视觉输入。做单模型比较时，固定网关别名对应的部署和回退设置。

用真实 LiteLLM Proxy 和本地脚本模型的集成测试验证转发。用 Runtime 的导入边界测试持续检查核心与网关或桌面适配器的依赖方向。

如果 OpenAI 兼容接口无法表达所需的模型行为，或网关延迟超过任务的已定义预算，重新评估接口或部署方案。
