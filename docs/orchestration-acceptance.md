# 编排技能与运行器验收 · 2026-10-22

0.4.0 新增七个技能：workflow-routing、task-orchestration、checkpoint-and-resume、failure-recovery、context-handoff、parallel-integration 和 acceptance-tracking。技能格式检查与原有技能一起执行，共 21 项通过。

## 可执行能力

- 单任务显式选择五种路线，默认保持完整 development 流程。
- 顺序依赖图验证、共享写入约束、实际结果交接和失败阻断；中断后不启动其他节点。
- 版本化检查点核对任务、源码、规则与阶段证据；源变化需要显式使旧阶段失效，不能重置修订预算。
- 输出当前任务交接、规范任务快照、失败类别和逐项验收报告。

## 真实客户端观察

在临时分页工作区，先用真实 Codex 完成 direct 开发阶段，再由代理在 verifier 调用前故意返回 7。显式 resume 后复用已完成开发，重新执行宿主检查和真实 verifier，最后 verified。开发阶段总共只执行一次，原测试文件不变。

在另一个临时工作区，两个有依赖的只读评审节点按顺序运行；第二个实际收到上游结果和证据位置，两个节点机器检查成功且评审 approve，图达到 verified。

六项真实技能评测均通过宿主门禁：普通评审、明确采访、指定范围修复、最小路线选择、任务交接和逐项验收。另人工核对了答复含义：交接保留失败基线与未验证项，验收追踪没有将单个通过输入推广为全部输入正确。

精简观察与实现指纹见 [验收收据](acceptance/2026-10-22-orchestration.json)。原始临时日志不纳入仓库，不包含用户项目数据或凭证。

## 回归范围与限制

回归覆盖：完成阶段复用、阶段文件丢失重跑、任务/源码/规则变化拒绝、显式重新验证、运行锁、最终检查失败后重新调用 verifier、修订预算不被恢复重置、只读评审状态、文档/direct 路线、依赖环/缺失/重复、共享范围、独立节点继续、人工中断停止及上游实际交接。

当前图顺序执行，不宣称自动并行或整个图自动恢复。仅有模拟测试的失败分支与上述真实 fixture 观察分开报告；六项技能场景不能证明所有技能在所有模型下都正确。未映射验收保留人工核对，不自动标为机器通过。Claude 原生验收和远端保护的认证缺口仍见 [前次修复记录](review-remediation.md)。
