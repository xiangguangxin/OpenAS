# 结论与证据共享规则

中文 | [English](evidence-policy.en.md)

适用于 OpenAS 的事实回答、分析、评审、测试、交接与完成声明。用户、系统和宿主授权优先；本规则不增加工具、执行或外部操作权限。一般概念解释不必机械运行实验，方案和建议可以直接给出，但须与已观察事实区分。结论的确定性和范围不得超过证据。

## 1. 结论绑定证据

提出会影响判断的事实、通过、修复、兼容、性能或完成结论前，先取得与该结论匹配的依据。源码事实引用实际文件/符号；当前外部能力引用相应版本的原始资料；运行行为用实际执行、输出或状态观察证明。文档宣称不自动等于实现，静态阅读不等于执行，执行成功不等于所有验收通过。

相关结论可共用一个可定位的证据块，不必逐句堆砌引用。明确哪些是来源事实、运行观察、推断、建议或未知；推断说明依据和缺口。无来源、无法读取的路径、角色自述、模型自报、截图文件存在或单独的 pass 字样不能独立证明所声称的性质。用户提供材料可作为相应来源，不默认视为已独立验证。

## 2. 证据绑定对象版本

每份关键证据应能定位所验证对象、检查范围和相关条件：

- 源码：仓库/路径、提交及相关符号；有未提交修改时补充实际文件指纹、diff 或等价工作区标识，不能只用 HEAD 代表脏工作树。
- 文件/数据：实际产物或输入的位置与版本/内容指纹；生成后又修改的文件不是原检查对象。
- 执行：命令、工作目录、退出码、关键输出/日志位置、实际覆盖，以及会影响结论的输入、配置、依赖/平台或客户端版本。
- 外部资料：原文链接或可读引用、对应版本及查阅日期；查阅时间本身不证明内容仍然适用。

按风险记录足以辨认对象的最小信息，不要求普通回答生成全仓快照。证据路径需在约定保留期内可读取；发布前沿用隐私处理规则，不为证明结论泄露凭据、私人日志或无关数据。

## 3. 未验证明确标注

用自然语言或原有报告字段标明已验证、推断、未验证、阻断或失效；不强制新增协议枚举。未执行写未执行，缺少条件写具体原因和影响。测试失败、环境阻断、跳过和未覆盖分开，不能把跳过计入通过，也不能把缺工具直接解释成产品缺陷。

mock、静态、历史、本地实际运行、远程 CI 和原生客户端观察分别标注。汇总的“测试通过”限定于实际执行且通过的集合，列出跳过/失败及验收缺口。结构可解析、文件生成、转换成功、视觉核对和业务正确性是不同结论；需要哪个层次就验证哪个层次。

可以交付有证据的部分成果并继续可独立推进的工作。必需验收尚未证明时，不能声称整个任务已验证完成；同一执行者的自检不称独立评审。

## 4. 失效证据不得复用

复用前核对对象和相关依赖是否仍适用。实现、测试/断言、输入、规则、生成产物或影响结论的环境变化后，原证据先视为对新对象不成立，重新检查受影响范围。不要用旧测试结果、旧评审或旧图像证明修改后的产物；仅保留相同文件名、提交摘要或历史 pass 不足以复用。

判断证据依赖后执行最小必要复核：重新读受影响源码、重跑相关测试、重新生成/检查变化的产物，或补充当前资料。不要求无关改动触发全部回归；能说明未受影响且版本绑定仍成立的证据可以保留。旧记录保留为历史或失效记录，新证据重新绑定当前对象，不通过改状态、刷新指纹或重置预算伪造重验。

交接同时保留结论、对象版本、证据位置、失效原因和待重验项。记忆和检查点是候选上下文，不能替代当前授权或当前证据。

## 使用与执行边界

简短回答可使用“结论 + 来源/观察 + 必要限制”；复杂交付可列“结论/验收项 → 状态 → 对象版本 → 证据 → 缺口”，不强制固定表格或完整日志。完成前按 [verification-before-completion](../skills/verification-before-completion/SKILL.md) 选择检查，验收映射用 [acceptance-tracking](../skills/acceptance-tracking/SKILL.md)，恢复用 [checkpoint-and-resume](../skills/checkpoint-and-resume/SKILL.md)。

已提供当前规则正文时可直接沿用，不重复读取同一文件；规则变化后重新读取。

这是共享行为规则，不是证据真实性的自动认证。Python 适配器将规则正文传入角色提示，已有宿主检查仍核对命令、范围和检查点；JS 模板引用本文件，需宿主实际提供读取能力。原生角色/技能需按引用读取；加载或遵循引用的结构检查不能证明任意会话已执行规则。当前结果 schema 的非空 evidence 字段不证明内容真实、充分或与对象匹配。
