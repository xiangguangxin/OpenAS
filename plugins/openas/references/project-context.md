# 按目标项目适配

OpenAS 提供协作方法，不预设业务领域、编程语言、构建系统或部署平台。角色与技能中的命令和路径只是示例，目标仓库与本次任务决定实际做法。

## 开始工作时确认

先复用会话中已经确认的事实，再按任务需要读取目标项目的 README、适用的 AGENTS.md / CLAUDE.md、依赖清单、构建配置、CI 和相关源码，不为小改动扫描整个仓库。

- **目标与范围**：用户要改变的行为、兼容要求、验收条件、允许修改的文件和已有改动。
- **项目结构**：相关模块、调用方、测试位置；区分插件安装目录、目标项目根目录与运行工作区。
- **运行方式**：实际语言和版本、平台、依赖管理器、构建/启动/检查命令；优先沿用项目已有命令，不假设 npm、pytest、CMake 或某种目录布局必然存在。
- **领域约束**：从当前源码与文档确认单位、数据契约、所有权、错误语义和外部依赖。只讨论本次改动涉及的约束，不把旧项目的协议、术语或组件带入新项目。
- **证据与能力**：哪些检查能在当前环境执行，哪些依赖真实客户端、设备、数据或服务；缺少工具时说明影响，不虚构验证结果。

能从仓库查到的信息自行读取；只有影响实现且无法推断的用户选择才需要提问。没有专用配置文件也能使用，不为接入插件强制增加配置或改写项目规则。

## 选择检查方式

| 当前任务 | 需要确认的证据示例 |
|---|---|
| Web / UI | 用户操作、状态变化、接口与可用的页面验证 |
| 服务 / API | 输入输出、错误响应、持久化、重试或并发（若涉及） |
| 库 / CLI / 脚本 | 公共接口、边界输入、退出码、输出与文件副作用 |
| 原生 / 嵌入式程序 | 对应构建、目标平台、资源生命周期及设备或运行时证据 |
| 数据处理 | 数据模式、缺失/重复值、转换结果与可复现输入 |
| 文档 / 配置 | 来源、链接、配置语义与项目已有校验器 |

这些是选择线索，不是每个任务都要完成的清单。没有编译步骤的项目无需制造构建，没有数据库的项目无需设计事务。

## 交接和记忆

交接时带上已确认的项目约束、实际检查命令及未验证项，避免下游角色重新猜测技术栈。项目记忆只从目标项目读取；历史演示和迁移证据不能当作新项目事实，也不自动授予执行历史任务的权限。
