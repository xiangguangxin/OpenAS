# 架构符合性检查

确认目标版本、检查范围和有效的架构说明、ADR、接口契约及已接受例外。读取实际代码、构建配置和调用方；没有设计基线时先区分可观察的现状与待确认的意图，不把目录命名或个人偏好当成架构约束。默认只读，发现问题不自动修复。

## 从约束追踪实现

将适用约束对应到模块和代码位置，按风险检查：

- 依赖方向、禁止的跨层调用、循环依赖及公共入口是否符合约定；区分源码依赖、构建依赖和运行时调用。
- 数据写入权、状态所有权和资源生命周期是否越过既定边界。
- 接口输入输出、单位、错误语义及相关的兼容、超时、重试和幂等行为是否一致。

静态引用只证明可见的依赖，不能直接证明运行时行为。对动态加载、生成代码、反射或配置注入说明检查限制；只在相关时读取对应入口，不因静态图缺边断言没有调用。已有检查器优先复用，缺少工具时用定向代码追踪，不默认安装新依赖或执行目标程序。

## 判断偏差与影响

每个发现保留稳定 ID、被违反的约束及其来源、实现位置、具体依赖路径或行为反例、影响和建议处理方式。区分未批准的偏差、仍有效的例外与已过时的设计；实现和文档不同不自动等于实现错误。证据不足标待确认，例外核对适用范围和重新评估条件。

只对有实际约束的边界建议自动化检查，例如禁止依赖或契约验证；避免把当前全部目录关系冻结成规则。普通实现缺陷交给 [requesting-code-review](../requesting-code-review/SKILL.md)，需改变边界或分阶段改造时交给 [architecture-evolution](../architecture-evolution/SKILL.md)。

交付基线与覆盖范围、约束到实现的核对结果、偏差和例外、未检查项及建议。没有发现只表示本轮范围内未发现偏差，不表示设计最优、运行正确或已获发布授权。
