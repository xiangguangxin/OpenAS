# 按读者任务选择文档

此表是核对点，不是每个文档都要复制的模板。先复用项目已有文档，避免同一事实在多处产生不同版本。

| 类型 | 需要回答的问题 | 重点核对 |
| --- | --- | --- |
| README | 项目解决什么问题、适合谁、如何开始？ | 功能与限制、最短可行示例、安装前提、深入文档入口、许可证 |
| 入门/教程 | 新用户怎样完成一个真实任务？ | 执行目录、版本、输入、步骤、预期输出、常见失败；教程示例连贯可执行 |
| 设计文档 | 准备做什么、为何这样选、如何实现与验证？ | 需求与非目标、调研依据；先用总览架构图展示边界、组件和连接，再用简洁文字解释职责、逻辑关系、输入到输出的数据流及关键状态变化；补充方案与技术决策、接口、风险和验收映射；拟议与已实现分开 |
| 架构说明 | 组件如何分工、为什么这样设计？ | 系统边界、数据/控制流、接口、关键决策和代价；当前实现与建议设计分开 |
| API/CLI 参考 | 每个接口如何正确使用？ | 参数、类型、默认值、单位、返回值、错误、退出码、版本兼容性；与实际入口一致 |
| 部署/运维 | 如何配置、运行、观察和恢复？ | 环境、配置来源、启动、健康检查、日志、升级、备份/恢复及不可逆步骤 |
| 排障指南 | 遇到某个症状先检查什么？ | 症状、前提、诊断命令、输出解释、修复及复验；假设不能写成已确认根因 |
| 贡献指南 | 怎样提交可评审的改动？ | 开发环境、现有检查命令、提交与评审方式；与 CI、仓库规则一致 |

写作时先给结果或最短路径，再补分支和原理；引用公共配置或接口来源，避免重复维护全部默认值。用户只要求润色时，以现有事实为边界，发现事实冲突则修正或明确待确认。
