# 项目文档

先确认读者要完成的任务及用户指定文件。读取 [项目约定](../../references/project-context.md)、现有文档、相关源码和 CI，沿用项目语言、目录与风格。润色任务保留正确含义，不为改措辞重构整套文档。

尚无实现的新项目可以依据需求、调研和设计决策编写拟议设计文档，明确文档状态。需要从市场调研串起完整设计时，按 [完整流程与交付结构](../solution-design/references/research-to-design.md) 汇总实际产物；写作时保留未知与冲突，不擅自补出已经确定的架构。

## 选择内容

根据交付物按需读取 [文档类型与核对点](references/document-types.md)。先写读者最需要的结果和操作路径，再补必要原理；不强制每个文档包含全部章节。

- 每项功能、参数、默认值和限制对应源码、配置、测试或可信资料。区分当前能力、可选依赖、实验特性和未来计划。
- 命令说明执行目录、前提、必要输入及预期结果。示例使用占位值，不暴露凭据，不将宿主临时路径写成通用路径。
- 接口说明包含输入输出、单位、错误和兼容行为；部署及运维说明覆盖配置、启动、健康检查、故障定位和适用的恢复方式。
- 图表使用 [technical-diagrams](../technical-diagrams/SKILL.md)。链接优先项目内相对路径；对代码说明保留稳定的符号/路径及版本背景，避免大段复制易过时实现。

## 核对与交付

执行项目已有文档检查，核对相对链接、代码围栏、示例与参数。按风险在隔离目录验证安装或使用示例；有破坏性、外部写入或凭据需求的命令不得仅为验证文档就执行。无法运行时说明具体未验证项，不能声称示例已跑通。

保持修改与请求有关，检查 diff 和图文一致性。交付变更位置、主要内容及验证范围。需要角色协作时可由 tech-writer 编写、主执行者或 verifier 执行检查；普通文档修改不要求完整开发团队。
