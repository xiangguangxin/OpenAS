# 集成测试

先读调用链、边界契约、现有测试入口与允许修改范围。确认本次要证明哪些组件协作，哪些依赖必须真实运行，哪些可以替代，以及替代后无法证明什么。

## 选择边界与预言

围绕实际协议和风险选场景，如输入输出转换、错误传播、事务提交或回滚、重试、幂等性与兼容性；不机械要求每个项目覆盖所有类别。断言来自公开接口、需求或可信参考，既检查返回值，也检查相关持久状态与副作用。

当验证数据库语义时使用相符的真实数据库或明确记录差异；mock 调用成功不能证明事务、网络或部署行为。只为关键组合保留端到端路径，避免将所有内部细节耦合到测试。

## 隔离与生命周期

沿用项目已有工具。为每次测试隔离命名空间、数据、端口和临时目录；建立所需最小夹具，注册异常路径也能执行的清理，并仅清理本次创建的资源。并行测试不得共享可变默认状态。服务启动采用有截止时间的就绪探测，避免固定睡眠；失败时保留可定位阶段的日志。

外部服务按现有授权运行，不连接未指定的生产环境或自行安装依赖。超时和重试与接口语义一致，不用无限重试掩盖缺陷。时序问题优先通过事件或可控时钟验证，无法消除的环境依赖写入限制。

## 执行与交付

缺陷回归先确认旧行为在目标场景失败，修复后运行同一场景及相关回归。失败时区分夹具、环境、断言与产品行为，记录可复现命令、输入和关键日志，不修改产品逻辑来让测试通过。

交付测试文件、真实/替代依赖及版本、数据隔离和清理方式、命令与退出码、断言覆盖及未验证性质。按 [完成前验证](../verification-before-completion/SKILL.md) 报告结果；[test-engineer](../../agents/test-engineer.md) 建设测试，developer 修复产品缺陷，verifier 独立验收。
