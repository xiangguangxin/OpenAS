# 技术文档绘图

将用户要求表达的结构或流程变成准确、可读、可维护的图。默认在当前仓库本地完成，不依赖外部服务。保留原文语言及项目图形风格。

## 选择方案

- 流程、状态转移、事务时序：优先 Mermaid。文档已有 Mermaid 时保持一致；需要独立图片时可用本地 Mermaid CLI 导出 SVG。
- 指针、内存地址、记录字段、精确布局：优先原生 SVG。文字、箭头和端口布局可精确控制，保持真正的矢量文本与线条。
- 节点较多、需要自动布局的系统架构：本地可用 D2 时考虑 D2，保留 .d2 源文件及 SVG；否则用 Mermaid 或 SVG。
- 用户需要拖动编辑、在线协作：可用已连接的 tldraw/FigJam；未连接时不假装可调用，也不阻塞本地绘图。未经请求不上传仓库内容。
- 不将位图包装进 SVG 冒充矢量图；算法和数据结构图不默认使用生成式图片。

按需要阅读 [工具选择与命令](references/tools.md)，不要为了一个简单图安装整套绘图工具。

## 先确定图意，再排版

1. 阅读关联源码或文档，列出节点、边、方向、状态和前提；将当前连接快照与动态执行顺序分清。
2. 一张图聚焦一个问题。架构表达组件和接口，时序表达先后，状态图表达状态与事件；必要时拆图。
3. 通过边标签或独立箭头区分调用、数据、事件和返回；所有箭头说明语义。逻辑关系不冒充部署关系，静态依赖不冒充运行顺序。
4. 核对图中每个组件、接口、状态和方向均有当前项目的来源；标明边界、异常分支及省略内容，不把其他项目的同名概念当作当前实现。

## SVG 与文档约定

- 图片沿用项目已有位置；无约定时放在目标 Markdown 同目录的 images/ 下，文件名用英文短横线。Markdown 使用相对图片链接，替代文本沿用文档语言。
- SVG 使用 viewBox，提供 title、desc；正文默认 16–18px，标题 24–30px，留足边距。参考 [可复用配色与箭头模板](assets/diagram-template.svg)。
- 颜色服从文档已有约定；没有约定时选择少量颜色并在图例中定义。图例和文字必须能独立说明差异，不只依赖颜色。
- 使用 XML 转义文字中的 &、<、>。ID 和 marker 引用唯一、完整；箭头避开文字和节点边框，不让线从无关节点中穿过。
- 中文字体使用 Noto Sans CJK SC、Microsoft YaHei、sans-serif 回退。预览和目标环境可能不同，不能把本机字体效果当成跨平台保证。
- 保留已有正确说明，不在图中堆放全部正文。精确绘图所用脚本只有后续确实需要重生成时才保留。

## 验证与交付

- SVG 用 `python3 <本技能目录>/scripts/check_svg.py <图片路径>` 检查 XML、尺寸和本地引用。此脚本不是排版验证器或安全扫描器。
- 使用可用浏览器或 SVG 渲染工具导出预览并检查：中文、遮挡、裁切、箭头方向、图例和缩放可读性。没有预览工具时明确只完成结构检查，不宣称视觉检查通过。
- Mermaid/D2 若已使用渲染器则检查其退出码及输出；没有渲染器可保留可读源，但不得称已导出。
- 检查 Markdown 图片链接与 git diff --check，核对图与源码一致。
- 交付图文件和嵌入位置，简述图的颜色与连接含义。只有用户要求时才提交或推送；本技能本身不授予发布权限。

用户可说：“为这个服务的登录流程画时序图并插入文档”或“把数据处理模块的依赖关系画成可维护的架构图”。
