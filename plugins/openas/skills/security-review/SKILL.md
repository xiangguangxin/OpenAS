# 安全评审

先确认授权对象、版本、入口、资产与数据类别、运行方式和评审范围。读取真实设计、配置及调用方；任务只要求评审时保持只读，不因通用风险清单扩大扫描范围。

## 建立边界与攻击路径

标出不可信输入如何跨越进程、网络、身份、权限和存储边界，确定攻击者实际能控制什么。沿调用链检查认证与授权、解析和输入处理、敏感数据流、凭据引用、日志和网络暴露；依赖与构建来源按项目风险检查，不要求每次完整审计所有类别。

针对候选问题说明入口、攻击前提、缺失控制、影响与现有缓解。认证成功不能代替对象级授权；前端校验不能代替服务端边界。配置缺失需核对运行时默认值与部署覆盖，避免仅凭局部代码认定可利用。

## 核实与安全复现

优先静态追踪和最小隔离实验。仅在已授权环境运行验证，不访问无关系统、不提取或输出秘密值；敏感证据采用脱敏位置和结构描述。不能复现时将推断及所缺证据写清楚，不把风险假设当已确认漏洞。

涉及当前漏洞公告、受影响版本或补丁时核对官方公告及实际安装版本、可达路径与配置。仅有依赖名称或版本命中不足以证明可利用；无法联网时说明时效缺口，不编造公告编号。

## 交付与复查

依 [协作契约](../../references/team-contract.md) 输出稳定问题 ID、位置、前提、证据、影响、严重度、修复建议和回归方法。结论可无发现，但需列出覆盖范围、未验证项及剩余风险，不能由局部评审宣称系统绝对安全。

[security-reviewer](../../agents/security-reviewer.md) 负责评审，developer 或 it 修复。复查既验证攻击路径被阻断，也检查合法路径仍可用；不能只确认新增了某个校验字符串。
