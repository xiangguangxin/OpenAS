# 演示文稿制作

本文件由 OpenAS 于 2026-10-24 重写与融合。方法来源、改动和条款见 [NOTICE](NOTICE.md) 与 [融合来源记录](FUSION_SOURCES.json)；配套生成与检查代码独立编写，未复制上游运行脚本、字体或图像。

## 从材料到叙事

先复用已确认的受众、目标、语言、时长、品牌、材料和输出格式。用户已经明确要制作时直接推进；缺少风格偏好可采用简洁商务样式并说明假设。缺失真实数据时先完成结构与有依据的部分，不编造客户名称、作者、测量值、引用或业务收益。

只要求提纲时交付提纲；要 PPTX 时交付实际文件。新建文稿默认 16:9，以演讲时间和内容难度决定页数。先组织少量核心观点，再安排问题背景、方法/方案、证据、限制和行动；不要将报告的每一段直接搬成一页，也不强迫所有场景使用同一叙事模板。

每页明确一个主要观点、支持证据、视觉表达和演讲备注；总讲述预算含过渡及必要问答。来源与定量条件放在短注和备注中；示例数据显式标为示例。科学或工程结果保留原始图、单位、样本和不确定性，不能用生成图片重画真实数据来制造漂亮结果。

## 设计与可编辑输出

统一画布、边距、标题层级、配色和目标环境实际可用的字体。优先用留白、对齐及布局变化表达层次；内容过多时删减或拆页，避免不断缩小文字。图像保持比例并提供说明，配色不能成为唯一的信息编码。

正文使用原生文字，简单图表和表格保留原生对象与底层数据。整页图片无法提供等价的编辑和可访问能力，不能冒充可编辑 PPT。需要图解时可按需使用 [technical-diagrams](../technical-diagrams/SKILL.md)，核对最终插入格式与实际可编辑范围。

新建文稿可用本技能的 JSON + python-pptx 工具，详见 [源稿、环境与生成](references/authoring.md)。项目已有适合的生成工具或用户指定实现时可复用；不继承来源中仅适用于其环境的 PptxGenJS 强制规则，不为装饰图默认调用收费服务或上传客户材料。

现有公司模板或复杂 PPT 先在副本中检查页面、母版、字体和对象，再选择保真编辑路径。配套生成器用于按 JSON 新建文稿，不承诺任意模板、SmartArt、宏、动画或嵌入对象的无损往返；不能把重新排版后的近似版本称为原模板保真编辑。

## 执行与验证

在本次任务允许的工作目录组织 JSON 源稿、资源和输出。先运行环境检查；需要依赖时使用任务隔离环境，按既有授权安装，不自动改系统或客户端全局配置。

1. 内容核对：结论、数值、单位、引用、页序、讲稿和时间预算与材料一致。
2. 结构核对：实际 PPTX 可以解析，文字/表格/图表对象和嵌入数据存在，图像不变形，几何范围与内容重叠没有未解释问题。
3. 实际渲染：通过本地 LibreOffice/PowerPoint 等真实渲染器导出 PDF/逐页图片，检查中文、字体替换、换行、溢出、对齐、对比度及图表标签；不能用自行绘制的示意预览替代。
4. 修正发现的问题，重新生成受影响产物并复核；没有发现问题时不制造缺陷来凑修复次数。逐页看过再记录视觉结论；渲染命令成功本身不是视觉通过。
5. 用户需要特定客户端或无障碍支持时，在相应环境验证编辑、放映、阅读顺序和访问能力；没有该环境时明确未验证项。

具体命令和检查边界见 [验证与交付](references/validation.md)。生成成功、结构通过、渲染完成、人工视觉核对和原生客户端验收分别记录；依赖不足时继续可完成的源稿与内容工作，明确实际产物，不能把 JSON 或改后缀的文件称为 PPTX。

## 交付

交付实际 `.pptx`、可重新生成的 JSON/源代码、必要资源、预览和简要检查记录。讲稿备注随 PPTX 保留，说明时间预算、数据来源、适用限制及未验证项；修改既有文稿时保留原文件。只交付需要的资源，不附带虚拟环境、工具安装包、缓存、凭据或完整私有运行日志。
